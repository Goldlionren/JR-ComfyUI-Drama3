# Windows 与 Ubuntu 安装部署

以下命令面向 x86-64 NVIDIA 主机。先选一种入口。**做配音工程**从「安装 ComfyUI 节点」开始；**只给应用提供实时语音**直接跳到「独立实时 API」。同机组合使用时可以共用项目目录。Windows 和 Ubuntu 各用自己的 Python、编译产物和服务状态，模型文件可从另一台机器复制。

## 安装 ComfyUI 节点

完整教师使用支持 FP8 的 NVIDIA GPU（代码要求 CUDA SM 8.9 或以上）、支持该卡的 CUDA 版 PyTorch，以及匹配的 Triton。教师会将部分专家权重放在系统内存；冷加载目标约为 13 GiB 空闲显存，整机还要容得下卸载的权重和运行时。已有完整实跑记录的硬件是 RTX 5090 32 GB。教师权重本身约 41.50 GB，另外为下载缓存、运行环境和工程留空间。

### Windows（PowerShell）

以下以秋叶版为例。先运行一次 ComfyUI，确认能打开画布。普通源码版或便携版也可用，将 `$comfy` 改为包含 `main.py` 的目录，`$py` 改为**实际启动该 ComfyUI 的 Python**（例如便携版的 `python_embeded\python.exe`）。从零安装 ComfyUI 可按照官方步骤准备环境。[ComfyUI 安装](https://docs.comfy.org/installation/manual_install) · [PyTorch 安装选择器](https://pytorch.org/get-started/locally/)

```powershell
$comfy = 'F:\ComfyUI-aki-v3\ComfyUI'
$py = 'F:\ComfyUI-aki-v3\python\python.exe'
$repo = Join-Path $comfy 'custom_nodes\JR-ComfyUI-Drama3'
git clone https://github.com/Goldlionren/JR-ComfyUI-Drama3.git $repo
Set-Location $repo
& $py -c "import torch,triton; print(torch.__version__, torch.version.cuda, torch.cuda.get_device_name(), torch.cuda.get_device_capability())"
& $py -m pip install hydra-core loguru descript-audiotools argbind tokenizers safetensors einops tqdm scipy huggingface_hub soundfile psutil
& $py -B jr_runtime/setup_runtime.py
& $py -B tools/fetch_teacher.py
```

如果已有独立开发目录，在该目录运行 `.\tools\install_local.ps1 -ComfyRoot $comfy` 创建目录联接，随后原地运行两个准备脚本即可。安装目录二选一。找不到 Triton 时，按当前 PyTorch 版本选择匹配的 Windows 包；本项目的一组实测版本为 Python 3.13、PyTorch 2.14.1+cu130、triton-windows 3.8.0.post29。[Windows Triton 版本对应表](https://github.com/woct0rdho/triton-windows)

### Ubuntu（Bash）

下面从 Ubuntu 24.04 的 Python 3.12 示例开始。已有 ComfyUI 环境时，直接设置 `COMFY` 和该环境的 `PY`，跳过安装 ComfyUI 的步骤。Ubuntu 22.04 默认的 Python 3.10 缺少本项目使用的 `hashlib.file_digest`，请在独立环境中使用 3.11 或更高版本。先确认 `nvidia-smi` 能识别显卡，并使 `ffmpeg` 可在 PATH 找到。

```bash
sudo apt update
sudo apt install git curl ffmpeg libsndfile1 build-essential python3-venv python3-dev
COMFY="$HOME/ComfyUI"
git clone https://github.com/Comfy-Org/ComfyUI.git "$COMFY"
python3 -m venv "$COMFY/.venv"
PY="$COMFY/.venv/bin/python"
"$PY" -m pip install -U pip
# 此例使用 CUDA 13.0 wheel。其他驱动按 PyTorch 官方选择器选相容版本。
"$PY" -m pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu130
"$PY" -m pip install -r "$COMFY/requirements.txt"
"$PY" -c "import torch,triton; print(torch.__version__, torch.version.cuda, torch.cuda.get_device_name(), torch.cuda.get_device_capability())"
```

```bash
REPO="$COMFY/custom_nodes/JR-ComfyUI-Drama3"
git clone https://github.com/Goldlionren/JR-ComfyUI-Drama3.git "$REPO"
cd "$REPO"
"$PY" -m pip install hydra-core loguru descript-audiotools argbind tokenizers safetensors einops tqdm scipy huggingface_hub soundfile psutil
"$PY" -B jr_runtime/setup_runtime.py
"$PY" -B tools/fetch_teacher.py
(cd "$COMFY" && "$PY" main.py --listen 127.0.0.1 --port 8188)
```

单独存放源码时可用 `ln -s /实际项目目录 "$COMFY/custom_nodes/JR-ComfyUI-Drama3"` 替代第二次克隆。使用支持 V3 `comfy_api.latest` 的 ComfyUI；历史基线是 ComfyUI 0.46.0。[官方安装步骤](https://docs.comfy.org/installation/manual_install)

### 检查第一次生成

**如果画布只用 8195 的实时节点**，把仓库安装或链接到 `custom_nodes/JR-ComfyUI-Drama3`，在 ComfyUI 的 Python 中确保 `numpy scipy soundfile safetensors aiohttp` 可导入，然后重新启动 ComfyUI。可以跳过 `setup_runtime.py` 和 `fetch_teacher.py`；完成同机的[实时引擎准备](NVFP4加速.md)后打开示例 07。API 单独装在另一个克隆时，GGUF 默认位置以启动 8195 的那个克隆为准。

重启目标 ComfyUI，打开 `http://127.0.0.1:8188`，拖入 [01 中英单句](../example_workflows/01-中英单句.json)。运行一句「你好，欢迎回来。」后，预览应可播放；教师输出为 44.1 kHz 单声道。也可在浏览器访问 `http://127.0.0.1:8188/object_info/JRDrama3Generate`，应返回带该节点 ID 的 JSON。首次权重校验和加载可能较慢。想启用可选的 FLA 内核时，再用同一解释器运行 `jr_runtime/setup_runtime.py --fla`。

## 独立实时 API（8195）

如果你手上已有本项目的 GGUF，或希望把模型放到独立磁盘，请先看 [NVFP4 加速与模型路径](NVFP4加速.md)。

服务器可使用普通 Python 3.11+ 虚拟环境和独立的项目克隆。客户端只需 HTTP。默认 NVFP4 使用编译目标 `120a`（RTX 5090 的 Blackwell 架构）、CUDA Toolkit 13 和 CUDA C++ 编译器；PyTorch 自带的 CUDA 库不包含 `nvcc`。Q4_K 路线使用发布的 Vulkan 程序，需驱动向 Vulkan 暴露 NVIDIA 设备；仅提供 `zh`、`en` 预设。两个后端任选其一。首次准备要联网；准备后在本机运行。[两种权重与大小](模型.md)

### Windows

需要 Git、curl 和 64 位 Python。编译 NVFP4 还需 VS 2022 Build Tools 的 C++ 桌面开发工作负载、Windows SDK、CMake、Ninja 与 CUDA 13；执行 `nvcc --version` 确认可见。从已有项目根目录开始，或先执行以下前两行克隆到当前目录。

```powershell
git clone https://github.com/Goldlionren/JR-ComfyUI-Drama3.git
Set-Location JR-ComfyUI-Drama3
py -3.12 -m venv .venv
$py = (Resolve-Path '.venv\Scripts\python.exe').Path
& $py -m pip install -r tools/requirements-realtime.txt
.\tools\prepare_realtime.ps1 -Backend nvfp4
& $py -B tools/realtime_service.py start --backend nvfp4
& $py -B tools/realtime_service.py status
(Invoke-RestMethod 'http://127.0.0.1:8195/health').data
$body = @{model='drama-3'; input='早上好。See you soon.'; voice='zh'; response_format='wav'} | ConvertTo-Json
Invoke-WebRequest -UseBasicParsing -Uri 'http://127.0.0.1:8195/v1/audio/speech' -Method Post -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body)) -OutFile 'demo.wav'
```

准备脚本支持 `-VsInstall 'C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools'` 显式指定工具链。使用 Q4_K 时，将准备和启动命令中的 `nvfp4` 都改为 `q4`。

### Ubuntu

Ubuntu 24.04 示例。NVFP4 需要 GCC/G++ 13 或更高、与其兼容的 CUDA 13 Toolkit（`nvcc` 在 PATH 中）。Ubuntu 22.04 自带的 GCC 和旧版系统 CUDA 不满足此组合，需自行选择相容工具链。Q4_K 可跳过 CUDA 编译工具，仅需要 Vulkan 加载器、NVIDIA Vulkan 驱动和解压工具。[NVIDIA Linux 安装指南](https://docs.nvidia.com/cuda/cuda-installation-guide-linux/) · [引擎 Linux 编译要求](https://github.com/0xShug0/audio.cpp/blob/066ea9862f41f4d7bcf996d5f00e464d8d28ace5/docs/build/linux.md)

```bash
sudo apt install git curl unzip util-linux python3-venv build-essential cmake ninja-build libvulkan1
git clone https://github.com/Goldlionren/JR-ComfyUI-Drama3.git
cd JR-ComfyUI-Drama3
python3 -m venv .venv
PY="$PWD/.venv/bin/python"
"$PY" -m pip install -r tools/requirements-realtime.txt
bash tools/prepare_realtime.sh nvfp4
"$PY" -B tools/realtime_service.py start --backend nvfp4
"$PY" -B tools/realtime_service.py status
curl -fsS http://127.0.0.1:8195/health
curl -fS http://127.0.0.1:8195/v1/audio/speech -H 'Content-Type: application/json' \
  -d '{"model":"drama-3","input":"早上好。See you soon.","voice":"zh","response_format":"wav"}' -o demo.wav
```

`/health` 应返回 `drama-3` 与所选后端，`demo.wav` 位于客户端执行命令的目录。Q4_K 对应 `bash tools/prepare_realtime.sh q4` 和 `start --backend q4`。两种系统都用同一启动器的 `stop` 停止网关和内部引擎；切换后端前先停止当前实例。服务日志在 `.runtime/provider-service/realtime.log` 与 `realtime-engine.log`。更多音色、语气、返回格式和远端访问设置见[实时 API](中英实时语音.md)。

## FP8 教师 API（8193）

先完成节点与 FP8 权重安装，备好 FFmpeg（或在同一 Python 环境安装 `imageio-ffmpeg`）。在**项目根目录**用启动 ComfyUI 的解释器执行。启动器创建 8194 精简队列和 8193 网关；同机已运行的 8188 装有插件时优先使用它。8193 接受整句，默认一次处理一个请求，忙时返回 HTTP 429 和 `Retry-After`。

```powershell
& $py -B tools/local_service.py start --comfy-root $comfy
& $py -B tools/local_service.py status
Invoke-RestMethod 'http://127.0.0.1:8193/health'
```

```bash
"$PY" -B tools/local_service.py start --comfy-root "$COMFY"
"$PY" -B tools/local_service.py status
curl -fsS http://127.0.0.1:8193/health
curl -fS http://127.0.0.1:8193/v1/audio/speech -H 'Content-Type: application/json' \
  -d '{"model":"drama-3","input":"欢迎回来。","voice":"alloy","response_format":"wav"}' -o teacher.wav
```

Windows 调用同一端点时可复用前面的 PowerShell 请求，将端口改为 `8193`，音色改为 `alloy`。用 `tools/local_service.py stop` 关闭启动器管理的进程。已有 8188 且只要网关时，可在项目根目录运行 `python -m provider --comfy-url http://127.0.0.1:8188 --voice-db "<本机 voices.sqlite3 的绝对路径>"`，在前台按 Ctrl+C 停止。支持 WAV、FLAC、MP3、Opus、AAC 和 24 kHz PCM。[Hermes 接入](Hermes接入.md)

## 常见问题

| 现象 | 检查方法 |
|---|---|
| 画布报节点缺失 | 检查启动日志中的插件导入错误、`custom_nodes` 下是否只有一份插件、依赖是否装进实际的 ComfyUI Python。H3 工作流另有独立节点包。 |
| 八分片被拒绝、校验值不符或找不到配置 | 选择包含 `config.json` 和十五个分片的同一目录，用下载器重新核验。GGUF 由 8195 服务读取。[模型目录](模型.md) |
| 内存不足或等待时间很长 | 除显存外查看系统可用 RAM。释放正在占用同一 GPU 的教师或实时引擎。首轮包括权重校验、加载及可能的内核编译。 |
| 8193 返回 503 | 检查 8188/8194 的节点注册和 `.runtime/provider-service/worker.log`、`provider.log`。单独启动的网关需要可用队列。 |
| 8195 无法访问、远端 403 | 在服务端先查 `/health`，然后核对回环 8196、网关地址、客户端网段与主机防火墙。[局域网配置](中英实时语音.md) |
| 找不到别处保存的声音 | 确认使用正确端口和后端，再对照两个进程使用的数据库绝对路径。[音色库迁移](声音资产.md) |

## 验证范围

历史 Windows 验收覆盖 RTX 5090 上的 FP8 教师、量化语音、真实 ComfyUI 工作流与 Hermes 输出。Ubuntu 22.04 WSL2 上使用独立 Python 3.12 运行了 8193 和 8195 的 HTTP 回归，覆盖格式转换、流式响应、音色注册与读取；这些接口测试使用测试后端。各功能的历史样本和人工听审范围见[功能验收](功能验收.md)。

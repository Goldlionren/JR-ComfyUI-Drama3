# Drama 3 中英实时语音 API 操作手册

8195 提供普通话、英语与混读。以下请求默认在服务端本机运行，首次可直接选仓库自带的 `zh` 或 `en`。其他机器调用时请按下文配置监听网卡与允许网段，将回环 IP 换成服务器的局域网 IP。

首次部署与自定义 GGUF 路径见 [Windows / Ubuntu NVFP4 加速指南](NVFP4加速.md)。服务运行后即可使用本手册的音色、语气和流式接口。

## 服务启停

在服务器上进入项目根目录并选用准备服务时的 Python。下面是 Windows 示例。Ubuntu 在项目根目录设置 `PY="$PWD/.venv/bin/python"`，使用 `"$PY" tools/realtime_service.py start --backend nvfp4`、`status`、`stop` 执行相同操作。

```powershell
Set-Location 'F:\AI\JR-ComfyUI-Drama3'
$py = (Resolve-Path '.venv\Scripts\python.exe').Path
```

**启动**。冷启动会校验权重、加载引擎并用中英文预热。本机曾测得约 28 秒。命令返回后，服务在后台运行，可以关闭 PowerShell，也可以在没有打开 ComfyUI 画布的情况下使用 Hermes。相同后端已启动时，启动器会复用进程。

```powershell
& $py -B .\tools\realtime_service.py start --backend nvfp4
```

**确认就绪**。第一条命令查看进程，应看到 `audiocpp_server.exe PID …` 和 `HTTP PID …, port 8195`。第二条命令会通过网关检查引擎，应显示 `drama-3` 和 `nvfp4`。

```powershell
& $py -B .\tools\realtime_service.py status
(Invoke-RestMethod 'http://127.0.0.1:8195/health').data | Select-Object id, backend
```

**从 Hermes 所在机器检查连通性**。下例假设服务器实际网卡地址为 `192.168.1.200`，并已在 `realtime-lan.txt` 启用该地址。请替换为自己的 IP。

```powershell
(Invoke-RestMethod 'http://192.168.1.200:8195/v1/models').data | Select-Object id, backend
```

**停止和重启**。等当前朗读完成，再在服务器执行以下两行。看到 `engine stopped` 和 `HTTP stopped` 即已关闭网关及推理引擎，引擎占用的显存随之释放。重启时再执行上面的启动和就绪检查。已保存的音色 ID 可继续使用。

```powershell
& $py -B .\tools\realtime_service.py stop
& $py -B .\tools\realtime_service.py status
```

## Hermes 配置

在**运行 Hermes 的机器**用 `hermes config path` 找到当前配置。编辑已有的 `tts:` 段，保留文件中的其他设置。下面可直接沿用你原来的 Edge 配置。

```yaml
tts:
  provider: openai
  use_gateway: false
  edge:
    voice: zh-CN-XiaoxiaoNeural
    speed: 1
  openai:
    base_url: http://127.0.0.1:8195/v1
    api_key: not-needed
    model: drama-3
    voice: "zh"
    speed: 1.0
```

- `provider: openai` 选择 Hermes 的 OpenAI 兼容客户端。`base_url` 填到 `/v1` 为止，客户端会追加 `/audio/speech`。`api_key` 是客户端要求的占位值，本地网关按来源网段限制访问。
- `edge:` 可以和 `openai:` 共存。日常使用只选择一个 `provider`。同一个配置只保留一个生效的 `openai:` 段。
- `openai.voice` 填音色列表里的 ID。换人声只改这一项。保留 `speed: 1.0`，此版本 Hermes 会省略默认语速参数。其他倍率会让文件合成请求携带 8195 不支持的 `speed`。
- 保存后，重新打开正在使用的 Hermes CLI 或桌面会话。如果是通过已安装的常驻 Hermes Gateway 接收消息，在运行它的机器上执行 `hermes gateway restart` 让配置生效。更换 Hermes 人声无需重启 Drama 3。

**验证自动朗读**。在启用语音输出的 Hermes 会话中，让它只回答一句「早上好。See you at nine.」。在 Hermes CLI 中，`/voice tts` 用于切换朗读开关。应听到同一个人读完中文与英文。

**验证带语气的文件合成**时，可以对 Hermes 说「请调用 `text_to_speech`，把『门已经关好了。』以 `instructions=whisper` 合成，`output_path` 使用 `drama-whisper.wav`。」显式给出 `.wav` 后缀，文件工具就会选择 8195 支持的 WAV。省略后缀或输出路径可能会请求 MP3 并收到 HTTP 400。当前 Hermes 的自动朗读路径只发送台词、模型、人声和 PCM 格式。要精确控制每段语气，可使用这个文件工具或下文的 HTTP 示例。

## 直接调用 API

以下 PowerShell 示例可以在服务器或允许的 Windows 客户端运行。先在同一个窗口运行这段，定义一个合成命令。它将中文按 UTF-8 发送，显式要求 WAV，并返回生成文件的路径。默认使用内置参考音 `zh`，省略 `-Seed` 时由服务随机采样。

```powershell
$api = 'http://127.0.0.1:8195/v1'
$voiceId = 'zh'

function Save-DramaSpeech {
    param(
        [Parameter(Mandatory)] [AllowEmptyString()] [string] $Text,
        [Parameter(Mandatory)] [string] $OutFile,
        [string] $Voice = $voiceId,
        [string] $Instructions,
        [uint32] $Seed
    )
    $body = @{
        model = 'drama-3'
        input = $Text
        voice = $Voice
        response_format = 'wav'
    }
    if ($Instructions) { $body.instructions = $Instructions }
    if ($PSBoundParameters.ContainsKey('Seed')) { $body.seed = $Seed }
    $json = $body | ConvertTo-Json
    Invoke-WebRequest -UseBasicParsing -Method Post -Uri "$api/audio/speech" `
        -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($json)) `
        -OutFile $OutFile -ErrorAction Stop
    Get-Item -LiteralPath $OutFile
}
```

**合成并试听第一段 WAV**。文件保存在执行命令的当前目录，相同文件名会被覆盖。最后一行会用系统默认播放器打开文件。

```powershell
Save-DramaSpeech -Text '早上好。See you at nine.' -OutFile '.\drama-test.wav'
Invoke-Item '.\drama-test.wav'
```

如果 Hermes 在 Linux 上，或你在 macOS 上调试，同一个请求可直接用下面的 Bash 命令发送。成功后当前目录会得到 `drama-test.wav`。

```bash
curl --fail --show-error --silent 'http://127.0.0.1:8195/v1/audio/speech' \
  -H 'Content-Type: application/json; charset=utf-8' \
  --data-binary @- --output drama-test.wav <<'JSON'
{
  "model": "drama-3",
  "voice": "zh",
  "input": "早上好。See you at nine.",
  "response_format": "wav"
}
JSON
```

## 更换或注册人声

**使用已有音色**。列出当前服务的音色。内置的 `zh` 和 `en` 也各自是一种人声，两者都能读中英文。`source=library` 表示已保存的版本。使用列表里的完整 `id` 调用，显示名称仅供辨认。

```powershell
$api = 'http://127.0.0.1:8195/v1'
(Invoke-RestMethod "$api/audio/voices").data | Select-Object name, id, source | Format-List
```

在上节的窗口中，给同一句话换成内置人声即可试听。要让 Hermes 长期使用它，把 `tts.openai.voice` 改为 `"en"` 或选中的完整 ID。

```powershell
Save-DramaSpeech -Text '明天见。See you tomorrow.' -Voice 'en' -OutFile '.\voice-en.wav'
```

**保存自己的参考音**时，准备一段清晰的单人录音和逐字稿。录音使用单声道或立体声的 PCM16 WAV，原文件上限为 5 MiB。`reference_text` 填录音里实际说的话，保留原语言。`input` 填这次要读的新台词。下面用项目自带的英文录音演示，先在**项目根目录**执行。换成自己的录音时，同时替换文件路径、名称与逐字稿。

```powershell
$api = 'http://127.0.0.1:8195/v1'
$clip = Get-Item '.\example_workflows\jr-benchmark-references\en.wav'
$reference = @{
    type = 'base64'
    data = [Convert]::ToBase64String([IO.File]::ReadAllBytes($clip.FullName))
}
$transcript = 'Early in the morning, I opened the window and heard birds singing in the garden. The air was cool and the street was quiet.'
```

在同一个窗口执行以下命令即可保存版本。若想先听效果，可以直接使用本节末尾的临时试听命令。

```powershell
$registration = @{
    name = '英语旁白示例'
    language = 'en'
    voice_ref = $reference
    reference_text = $transcript
} | ConvertTo-Json -Depth 4
$saved = Invoke-RestMethod -Method Post -Uri "$api/audio/voices" `
    -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($registration))
$saved | Select-Object name, id
```

复制返回的 ID 到 Hermes 的 `tts.openai.voice`，或用下面一行试听。**使用已保存的 ID 合成时，只传 `voice` 和新台词等合成参数，省去 `voice_ref` 与 `reference_text`。** 同一录音、逐字稿及名称等元数据重复注册会返回同一 ID。更换录音、逐字稿或元数据会产生新 ID，之前的版本仍可选用。

```powershell
Save-DramaSpeech -Voice $saved.id -Text '我们明天九点见。' -OutFile '.\new-voice.wav'
```

**从 ComfyUI 保存**。把录音和匹配的逐字稿接到「Drama 3 · 保存音色版本」，执行一次，复制输出的 `voice_id`。若想保留某次生成中喜欢的人声，也可截取其中一句清晰的独白，用该句台词作逐字稿保存新版本。

将 API 和画布指向同一份本机 `voices.sqlite3` 即可复用声音。[Windows 与 Ubuntu 的默认和自定义路径](声音资产.md)如要迁移音色，可在没有写入时备份该库。使用自定义用户目录时，将两边的 `JR_DRAMA3_VOICE_DB` 指向同一个本机数据库文件，并重新启动相应进程。

**临时试听一段录音**。在准备好 `$reference` 和 `$transcript` 后，可跳过注册，将它们直接发到合成端点。这适合挑选录音，返回值是音频。保存 ID 和临时传参考音都需要 NVFP4 后端。

```powershell
$preview = @{
    model = 'drama-3'
    input = '请把蓝色的文件夹放在桌上。'
    voice_ref = $reference
    reference_text = $transcript
    response_format = 'wav'
} | ConvertTo-Json -Depth 4
Invoke-WebRequest -UseBasicParsing -Method Post -Uri "$api/audio/speech" `
    -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($preview)) `
    -OutFile '.\voice-preview.wav'
```

## 调整语气

**整段语气**由 `instructions` 控制。留空是自然朗读，`whisper` 是耳语，`icy calm` 是冷静克制。服务把简短的纯文本提示应用到每个分句。对比时固定台词、人声和种子，只改提示。下面三条命令使用上文定义的 `Save-DramaSpeech`。

```powershell
$line = '门已经关好了。'
Save-DramaSpeech -Text $line -Seed 37003 -OutFile '.\tone-natural.wav'
Save-DramaSpeech -Text $line -Seed 37003 -Instructions 'whisper' -OutFile '.\tone-whisper.wav'
Save-DramaSpeech -Text $line -Seed 37003 -Instructions 'icy calm' -OutFile '.\tone-calm.wav'
```

**局部语气**写进 `input`，用成对标签包住需要变化的那几个字或那一句。下面的第一句自然读，第二句用耳语。英语同样可写 `Stay here. <whisper>Someone is outside.</whisper>`。不同参考人声对提示的反应强弱有所不同。[Fish Audio 表演标记说明](https://huggingface.co/spaces/fishaudio/Drama-3/blob/a3e529d3b490d03dcab837b46334e4ff70f696f8/README.md)

```powershell
Save-DramaSpeech -Text '门已经关好了。<whisper>别让他听见。</whisper>' -Seed 37003 -OutFile '.\tone-local.wav'
```

## 音频格式与流式调用

| 调用方式 | 请求设置 | 如何使用响应 |
|---|---|---|
| 生成 WAV 文件 | `response_format: "wav"` | 完整的 44,100 Hz 单声道 WAV，可直接用播放器打开 |
| Hermes 自动朗读、自写 24 kHz 播放器 | `response_format: "pcm"`，请求头 `Accept: application/octet-stream` | 边收边播，24,000 Hz、单声道、16 位小端有符号 PCM |
| 原生 PCM | `response_format: "pcm"`，使用默认的 `Accept: */*` | 边收边播，44,100 Hz，同样为单声道 PCM16LE |
| SSE 事件流 | `response_format: "pcm"`，`stream_format: "sse"` | 44,100 Hz。依次解码 `speech.audio.delta` 事件里 Base64 编码的 `audio`，最后核对 `speech.audio.done` 的 `stop="complete"` 和 `samples` |

普通 PCM 和 SSE 都没有 WAV 文件头。自写播放器应读取响应头 `X-Sample-Rate`，按实际采样率播放。服务以 `X-Speech-Seed` 返回本次种子。Hermes 的 OpenAI 客户端会自动发送表中 24 kHz 所需的请求头。

**Python 流式示例**。已安装 `requests` 的机器可以运行以下代码。它按 Hermes 使用的方式接收每块 PCM，按响应头给出的采样率写入 `hermes-stream.wav`。接实时播放器时，把循环中收到的块交给音频输出设备即可。

```python
import wave
import requests

url = "http://127.0.0.1:8195/v1/audio/speech"
payload = {
    "model": "drama-3",
    "voice": "zh",
    "input": "早上好。See you at nine.",
    "response_format": "pcm",
}
with requests.post(url, json=payload, headers={"Accept": "application/octet-stream"},
                   stream=True, timeout=(5, 120)) as response:
    response.raise_for_status()
    with wave.open("hermes-stream.wav", "wb") as out:
        out.setnchannels(1)
        out.setsampwidth(2)
        out.setframerate(int(response.headers["X-Sample-Rate"]))
        for block in response.iter_content(chunk_size=4096):
            out.writeframesraw(block)
```

## 接口参数与排查

| 方法与路径 | 用途 |
|---|---|
| `GET /health` 或 `GET /v1/models` | 检查网关及上游引擎，查看 `data[0].id` 和 `data[0].backend` |
| `GET /v1/audio/voices` | 查看内置音色和当前可用的已保存 ID |
| `POST /v1/audio/voices` | 在 NVFP4 音色库注册版本，返回 `id`。必填 `name`、`voice_ref`、`reference_text`，可选字符串 `language`、`description`、`tags` |
| `POST /v1/audio/speech` | 发送 UTF-8 JSON，请求合成 WAV、PCM 或 SSE |

**合成字段速查**

| 字段 | 取值与默认行为 |
|---|---|
| `input` | 必填字符串，最多 4096 个字符，可混读中英文。空串和纯空白是有效的静音请求。缺少字段或传入 `null` 会返回 HTTP 400 |
| `model`、`voice` | 模型默认为 `drama-3`。音色默认为 `zh`，也可用 `en` 或音色库中完整的 64 位十六进制 ID |
| `instructions` | 可选，整段语气。合并空白后最多 200 个 UTF-8 字节，中文通常每字占 3 字节。方括号和尖括号标签放入 `input` |
| `seed` | 可选整数，范围 0–4294967295。省略时每次随机。固定种子便于在同一后端比较语气 |
| `response_format`、`stream_format` | 默认分别为 `pcm`、`audio`。可选组合为 PCM/audio、PCM/SSE、WAV/audio |
| `voice_ref`、`reference_text` | 临时使用参考音时成对提供。前者形如 `{"type":"base64","data":"…"}`，后者为 1–4096 字的原语逐字稿 |

网关只把有台词的分句送给模型。同一请求中的空行、独立表情、标点、角色标记或单独的 `[whisper]`、`[laughs]` 会被跳过，后面的台词继续合成。将提示和台词放在同一句可保留表演效果，例如 `[laughs] 明天见。`。整条请求都没有台词时，HTTP 200 返回 20 ms 全零音频，沿用请求的采样率与格式，Hermes 可以继续播放下一句。

**按现象定位**

| 现象 | 检查和处理 |
|---|---|
| 本机也连不上 | 运行 `status` 和本机 `/health`。若返回端口占用，先查 8195 与内部引擎端口 8196 的占用进程。启动失败可看下方两份日志 |
| 本机通，另一台机器超时或报 403 | 在那台机器运行 `Test-NetConnection 192.168.1.200 -Port 8195`。超时时检查路由和 Windows 防火墙的 TCP 8195 入站范围。收到 403 时检查来源网段、访问地址和代理。客户端应直接使用服务器的局域网 IP |
| HTTP 400、找不到人声 | 读响应里的错误信息，先查 `/v1/models` 的后端及 `/v1/audio/voices` 的完整 ID。检查是否给保存的 ID 又带了参考音、是否请求了 MP3，或额外传了 `speed`、`lang`、`temperature` 等字段 |
| HTTP 429 | 当前只处理一条合成请求。按响应头 `Retry-After: 5` 等待 5 秒后重试 |
| 声音失真、音高或播放速度异常 | 先用同一 ID 生成 WAV 试听。若 WAV 正常，检查客户端是否把 44,100 Hz 与 24,000 Hz 混用，按 `X-Sample-Rate` 初始化 PCM 播放器 |
| 实际听到参考录音里的旧台词 | 用同一 ID 分别发送 `[whisper]` 和 `好的。😊`。前者应返回 20 ms 静音，后者只读「好的」。若有台词的句子仍复现，保留该次 `input` 和响应头 `X-Speech-Seed`，可按原输入与种子复测 |
| 改了配置，人声仍旧 | 在实际使用的 Hermes 配置中核对 `provider` 和 `openai.voice`，重开会话。用上文的 WAV 命令对比同一句台词 |
| 上游引擎错误或超时 | 先查本机健康接口和引擎日志，确认加载了正确权重、显存足够。需要恢复时按“服务启停”重启 |

**服务器日志**。在项目根目录执行，第一份是 HTTP 网关日志，第二份是推理引擎日志。

```powershell
Get-Content '.\.runtime\provider-service\realtime.log' -Tail 40
Get-Content '.\.runtime\provider-service\realtime-engine.log' -Tail 40
```

**局域网绑定**。网关启动时读取 `.runtime\provider-service\realtime-lan.txt`。以下为示例，首行指定监听网卡的地址和前缀，之后每行是一个额外允许的来源网段。网关同时保留回环地址。日常换音色无需改动此文件。只开放需要的来源网段；请同步调整 Windows 或 Ubuntu 防火墙入站范围，再重启实时服务。8196 是服务内部的回环端口，Hermes 始终连接 8195。

```text
192.168.1.200/24
192.168.100.0/24
```

新安装默认仅监听回环。要启用局域网，先确认首行中的 IP 确实属于服务器网卡，再把上例保存为 ASCII 或无 BOM 的 UTF-8 文本。Windows 路径为 `.runtime\provider-service\realtime-lan.txt`，Ubuntu 为 `.runtime/provider-service/realtime-lan.txt`。在远端用 `curl -fsS http://192.168.1.200:8195/health` 检查，并将 Hermes 配置中的 `127.0.0.1` 换成实际服务端 IP。8193 教师网关只监听回环。

## 在 ComfyUI 中使用

在 ComfyUI 重新加载插件后打开「07-中英实时语音」，点击「启用本机流式试听」，再排队生成。节点还会输出完整 AUDIO 和本次延迟报告。参考音色 `zh` 和 `en` 来自本项目的两段合成测试录音，两者均可朗读中英文。与 FP8 教师共用一张显卡时，可以先用「释放教师」腾出显存，切回教师前按“服务启停”中的命令释放量化引擎。

打开[实时音色与语气工作流](../example_workflows/08-实时音色与语气.json)，在「加载音频」里上传[示例录音 zh.wav](../example_workflows/jr-benchmark-references/zh.wav)，即可使用工作流预填的逐字稿。换成自己的声音时，选一段只有一人清楚说话的短录音，同时把「参考录音逐字稿」改成录音中实际说的话。`text` 填写要新生成的台词。连接录音后它会覆盖 `voice` 预设。音色库里的声音也可以直接用，将「检索与载入音色」的 AUDIO 和 transcript 分别连到这两个输入。

## 安装或切换引擎

首次在 Windows 机器部署时，先用准备脚本获取与验收相同的引擎和权重。每个后端需要约 21–23 GB 下载空间。Q4_K 使用 Vulkan，NVFP4 使用为 RTX 50 系列编译的 CUDA 引擎。准备 NVFP4 另需 Git、CUDA 13、支持 C++ 的 VS Build Tools 及 CMake/Ninja。

```powershell
.\tools\prepare_realtime.ps1 -Backend q4
# 或者准备同版本教师的 NVFP4
.\tools\prepare_realtime.ps1 -Backend nvfp4 -VsInstall 'C:/Program Files (x86)/Microsoft Visual Studio/2022/BuildTools'
& $py -B tools/realtime_service.py stop
& $py -B tools/realtime_service.py start --backend nvfp4
```

Q4_K 使用模型作者提供的权重与 speech.cpp 0.11.2，NVFP4 使用由项目的原始教师版本 `78e5ab7` 转换的权重和作者提供的 audio.cpp 补丁。模型受 Fish Audio Community License 约束。[Q4_K 模型卡](https://huggingface.co/sakasegawa/drama-3-GGUF) · [speech.cpp 发布包](https://github.com/nyosegawa/speech.cpp/releases/tag/v0.11.2) · [NVFP4 模型卡及补丁](https://huggingface.co/WonderChord/Drama3-V2-NVFP4-256E-GGUF) · [模型许可证](../licenses/Fish-Audio-Community-License.txt)

Ubuntu 使用 `bash tools/prepare_realtime.sh nvfp4` 或 `q4`，启动参数两种系统相同。[逐步安装](安装部署.md)

## RTX 5090 实测

默认后端为保留全部专家的 NVFP4。普通话和英语各选一段固定参考音，每组用一个短句和一个长段落，各测三个种子，合计 18 条热请求。首音从客户端发起请求前计至收到至少 20 ms 可播放 PCM，包含本地 HTTP 开销。RTF 为请求耗时除以音频时长。P95 用最近秩计算，每组仅有六条，因此表中的 P95 就是本组最大值。

| 语种 | 首音 P95 | RTF 中位数 | RTF P95 | Whisper 回读错误率 |
|---|---:|---:|---:|---:|
| 普通话 | 118 ms | 0.193 | 0.198 | 2.53% 字错率 |
| 英语 | 182 ms | 0.206 | 0.213 | 0.00% 词错率 |
| 中英混读 | 192 ms | 0.207 | 0.213 | 0.00% 混合错误率 |

混读按单个汉字和单个英文词计数。中文回读统一简繁和同义数字写法，原始转写保存在报告中。三组的末尾均通过回读核对。18 条音频与参考音的 CAMPPlus 余弦相似度最低为 0.839。每次生成后采样的整卡显存占用为 23.66–23.78 GiB。预存 80 ms PCM 的播放模拟中，18 条均连续供音。逐条耗时（`outputs/realtime-validation/nvfp4/timings.json`） · 原文、转写和音色相似度（`outputs/realtime-validation/nvfp4/asr.json`）

把混读工作流提交给独立 ComfyUI 实例后，WebSocket 收到了 30 块 PCM，并逐样本核对了最终预览。Chromium 中从提交到 Web Audio 调度开始播放的估计是 221 ms，整段 5.34 秒，各缓冲块之间没有可测的调度空档。这个数字测到浏览器音频时间线，声卡和扬声器的物理延迟需要单独测量。同种子的 PCM、SSE、WAV 三种接口交付了相同的样本。画布记录（`outputs/realtime-validation/nvfp4/canvas.json`） · 浏览器播放记录（`outputs/realtime-validation/nvfp4/browser.json`） · 音频格式核对（`outputs/realtime-validation/nvfp4/formats.json`）

首次启动会校验权重、加载常驻引擎并预热两种音色。本机一次完整启动用时 27.5 秒；服务就绪后，首条中文请求在 207 ms 收到可播放 PCM。旧版 FP8 教师在相同短句、参考音和种子下的历史热运行 RTF 为 10.25–10.62。旧版计时从渲染开始，新接口从客户端计时。FP8 历史结果（`outputs/teacher-validation/benchmark/cold-warm/summary.json`） · 启动后请求（`outputs/realtime-validation/nvfp4-sustained/timings.json`）

Q4_K 用相同台词做了对照。直接把多句文本交给原生引擎时出现末句缺失，项目服务因此沿用现有台本解析器分句，并在每句收到完成事件后继续。分句后 Q4_K 的英文和混读 RTF P95 分别为 0.774、0.727，超过本次 0.7 目标；一个混读样本的 ASR 转写重复了中文。NVFP4 通过了同一套速度和回读检查。已有全专家量化可以满足此机的实时目标，本次使用公开量化权重，没有训练新的蒸馏学生。Q4_K 原生回读（`outputs/realtime-validation/q4/asr.json`） · 分句后测速（`outputs/realtime-validation/q4-stream/timings.json`） · 分句后回读（`outputs/realtime-validation/q4-stream/asr.json`）

额外的持续播放测试交替朗读 11 句中英文，12.87 秒生成 65.48 秒音频，首段 PCM 为 107 ms。预存 80 ms 后全程没有断供。Whisper small 用中文模式一次转写整段，漏识别了倒数第二句英语（整段混合错误率 10.05%）。逐句以相同种子重建边界，确认 11 段与原录音逐字节一致，再按各句语言转写原音频，得到 3/209 个单位错误（1.44%），其中这句英语完整匹配。长稿测速（`outputs/realtime-validation/nvfp4-sustained/timings.json`） · 整段转写（`outputs/realtime-validation/nvfp4-sustained/asr.json`） · 逐句复核（`outputs/realtime-validation/nvfp4-sustained/asr-by-sentence.json`）

本机历史试听文件：中文（`outputs/realtime-validation/nvfp4/zh-1.wav`） · 英语（`outputs/realtime-validation/nvfp4/en-1.wav`） · 中英混读（`outputs/realtime-validation/nvfp4/mixed-1.wav`） · 65 秒连续混读（`outputs/realtime-validation/nvfp4-sustained/mixed-sustained-1.wav`）。

在本机固定台词和种子的对照中，用同一段英语参考人声说中文时，自然朗读的整句 RMS 为 −19.5 dBFS，加上局部耳语标签后为 −32.2 dBFS；同一人声说英语时分别为 −20.5 和 −40.7 dBFS。中文参考人声的中文耳语变化较小。九条样本的 Whisper 回读均与台词一致（忽略标点和大小写）。逐条对照（`outputs/realtime-voice-control/comparison.json`） · 中文自然朗读（`outputs/realtime-voice-control/zh-second-voice.wav`） · 同人声中文耳语（`outputs/realtime-voice-control/zh-second-voice-scoped-whisper.wav`）

## 复测

让量化服务常驻，使用新目录保存测试结果。第一条命令通过实际 HTTP 接口生成 18 条 WAV，第二条命令用本地 Whisper small 和 CAMPPlus 检查内容与音色。运行时断开长请求后，也已验证下一条请求能完成。中断与恢复记录（`outputs/realtime-validation/nvfp4/disconnect.json`）

```powershell
$out = 'outputs/realtime-recheck'
$camp = 'F:/ComfyUI-aki-v3/ComfyUI/models/IndexTTS-2.5/hf_cache/campplus_cn_common.bin'
& $py -B tools/benchmark_realtime.py --output $out
& $py -B tools/benchmark_realtime.py --output $out --review --speaker-model $camp
& $py -B tools/benchmark_realtime.py --output "$out-long" --sustained --repeats 1
& $py -B tools/benchmark_realtime.py --output "$out-long" --review-by-sentence --speaker-model $camp
```

# 声音资产、输出目录与搬家

**要保留一个喜欢的人声，先看它保存成什么。**「保存音色版本」和实时 API 注册的参考录音在 SQLite 数据库里。候选录音、剪辑锁定和最终导出的音轨分别存放。API 合成的 WAV 则保存在发起请求的客户端指定的位置。

这里列出的是**推理和配音工程**的资产。用参考录音克隆角色时，`voice_id` 指向保存的录音与逐字稿，生成时可再次调用。需要用一批录音训练模型时，数据集和训练输出目录由外部训练工具指定。[Windows 与 Ubuntu 训练目录示例](安装部署.md#需要训练)

### 工程里有什么

`project.jrdrama.zip` 用于恢复工程，`manifest.json` 可直接查看；语言目录有 `mix.wav` 和 `captions.srt`。选项可额外生成 `lines/000001.wav` 等逐句文件、`stems/001.wav` 等角色轨、`mix.flac`、`mix.mp3` 或带章节的 `book.m4b`。双语工程为每种语言保留各自音轨和字幕，以相同台词 ID 对照。

ZIP 内含原始逐句 WAV（`<语言>/source/`）、清单，以及导出时接入的角色参考 WAV、工作流或封面。交付总混音和可选分轨位于导出目录中。归档工程时复制**整个导出目录**；仅供恢复时可用 ZIP。在新机器把 ZIP 放入有效 `input` 或 `output`，在「恢复工程」选相应来源，填写相对于该根目录的路径。[工程格式实现](../jr_delivery_bundle.py)

## 让画布和 API 共用同一个声音

默认 ComfyUI 节点跟随有效 `user` 目录。独立 8195 网关识别秋叶安装或直接装在 `custom_nodes` 的项目；纯 API 克隆未识别到 ComfyUI 时回退到 `<项目>/.runtime/provider-service/voices.sqlite3`。跨 venv、符号链接或自定义 user 目录部署时，**显式给 ComfyUI 和两个启动器设置同一个本机文件绝对路径**最容易核对。手工运行 `python -m provider` 时也可传 `--voice-db`。

```powershell
$env:JR_DRAMA3_VOICE_DB = 'D:\Drama3 Assets\voices.sqlite3'
```

```bash
export JR_DRAMA3_VOICE_DB="$HOME/Drama3 Assets/voices.sqlite3"
```

分别从已设置该变量的环境启动或重启各进程。已有声库先复制到新路径，变量只选择位置。执行一次「保存音色版本」，再读取 `http://127.0.0.1:8195/v1/audio/voices`，确认同一完整 ID 出现在列表中。两个实时后端共用这套音色 ID。多台机器各有自己的本机 SQLite 库；远程客户端把 ID 发送给持有该库的服务器。

## 备份与恢复顺序

1. 等待录音与工程导出结束。停止可能写声库的服务和 ComfyUI，复制有效的 `voices.sqlite3`。如要在线备份，使用 SQLite 的 backup API 制作一致快照。
2. 一并复制原始输入、保存的工作流、`<output>/JR-Drama3/`、原生 Save Audio 成品、客户端另存的 WAV，以及需要交付的视频。还使用过 8194 输出时检查其独立目录。
3. 新机配置对应目录及 `JR_DRAMA3_VOICE_DB`，恢复同一个库后已有 ID 可继续使用。打开工程 ZIP 试听一条锁定录音，再用原 ID 调一次语音端点。模型与编译环境按目标系统另行准备。[模型迁移](模型.md)
